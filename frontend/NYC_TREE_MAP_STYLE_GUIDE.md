# NYC Tree Map 风格规范

本文档用于统一网页端和移动端的视觉修改方向。项目可以参考 NYC Tree Map 的公共服务地图气质，但不要照搬其品牌、Logo 或英文内容。

参考页面：https://tree-map.nycgovparks.org/

## 1. 风格目标

整体气质应接近“政府公共服务地图 + 城市树木档案”，而不是营销页或普通 App demo。

核心关键词：

- 地图优先
- 白底黑字
- 深绿强调
- 细灰边框
- 方正卡片
- 信息密度适中
- 公共服务可信感

界面要让用户感觉这是一个正式的城市树木服务平台，而不是临时做出来的移动端演示。

## 2. 色彩

优先使用已有 CSS 变量：

| 用途 | 变量 / 色值 | 使用场景 |
|---|---|---|
| 主文字 | `--nyc-black` `#16161d` | 标题、重要数字、主要文本 |
| 次要文字 | `--nyc-gray` `#58595b` | 描述、时间、辅助字段 |
| 主绿色 | `--nyc-green` `#50802c` | 主按钮、当前状态、重要强调 |
| 深绿色 | `--nyc-green-dark` `#3f6921` | 主按钮 hover、深色强调 |
| 浅绿色 | `--nyc-light-green` `#e0f0d4` | 轻提示、选中背景 |
| 页面背景 | `--nyc-page-bg` `#f8f8f8` | 页面底色 |
| 卡片背景 | `--nyc-panel-bg` `#ffffff` | 卡片、面板、抽屉 |
| 边框 | `--nyc-border` `#d8d8d2` | 卡片边框、分割线 |

使用规则：

- 主按钮必须是绿色底、白色字。
- 大面积背景保持白色或浅灰，不使用大渐变。
- 不用紫色、蓝紫渐变、装饰光斑、玻璃拟态背景。
- 状态色只用于状态本身，不要让整页变成某一种颜色。
- 警示用黄色/橙色，异常用红色，保持克制。

## 3. 字体与排版

- 字体沿用系统 sans-serif：英文优先 Helvetica/Arial，中文使用 PingFang SC / Microsoft YaHei / Noto Sans SC。
- 页面主标题可以较大，但卡片内标题要克制。
- 不使用负字距。
- 不用随屏幕宽度变化的字体大小。
- 内容区的辅助文字使用灰色，小字号，但必须可读。
- 标题下可以使用一条绿色短横线作为 NYC Tree Map 式强调。

推荐层级：

| 类型 | 建议 |
|---|---|
| 页面标题 | 24-30px，粗体 |
| 卡片标题 | 15-18px，粗体 |
| 正文 | 13-15px |
| 辅助信息 | 11-13px，灰色 |
| 数字指标 | 可使用等宽字体，保持清晰 |

## 4. 布局原则

地图类页面：

- 地图是主视觉，优先占据主要区域。
- 搜索框放在地图上方浮层。
- 树木详情使用底部 bottom sheet，不用页面中间大弹窗。
- 移动端底部保留固定 Tab，便于单手切换。

内容类页面：

- 使用浅灰页面背景 + 白色内容卡片。
- 页面不要堆叠“卡片套卡片”。
- 长内容要折叠或放进可展开区域。
- 移动端卡片信息要先展示核心字段，详情通过展开/抽屉呈现。

## 5. 卡片规范

卡片视觉：

- 背景白色。
- 边框使用 `--nyc-border`。
- 圆角尽量为 0；如必须使用圆角，不超过 8px。
- 少用阴影；移动端浮层可以使用很轻的阴影或 2-3px 的下沿阴影。
- 卡片标题左侧可以放 lucide 图标。

卡片内容：

- 第一行放主识别信息，如树木编号、工单号、线索号。
- 第二行放树种、状态、角色或地点。
- 时间、创建人、说明放辅助信息层。
- 操作按钮放底部或右侧，不能挤占主要信息。

## 6. 按钮与控件

主按钮：

- 绿色底。
- 白色字。
- 方正边框。
- 用于“提交、打卡、到达后处置、到达后复核”等明确行动。

次按钮：

- 白底。
- 灰色或黑色边框。
- 黑色/灰色文字。
- 用于“退出导航、取消、查看详情”等次要行动。

移动端任务卡片工单行动按钮：

- 用于“去现场处置”“去现场复核”。
- 暗红色底：`#8f1f24`。
- hover / focus 暗红色：`#6f171b`。
- 字体必须为白色。
- 高度：`26px`。
- 左右内边距：`9px`。
- 字号：`11px`。
- 图标尺寸：`12px`。
- 形态保持方正，不使用胶囊圆角。
- 只作为卡片内的小行动按钮，不要做成占满整行的大按钮。

图标：

- 继续使用 `lucide-vue-next`。
- 有现成图标时不手写 SVG。
- 移动端底部 Tab 使用图标 + 短文字。

不要做：

- 不要用大号圆角胶囊按钮堆满页面。
- 不要让绿色按钮出现灰色文字。
- 不要用难以理解的纯图标按钮，除非有明确语义。

## 7. 移动端规范

移动端顶部：

- 采用黑色机构条 + 白色品牌区。
- 品牌区显示平台名称和一句英文/中文副标题。
- 不写“移动端”“demo”等开发视角文字。
- 登录页顶部黑色机构条固定高度为 `24px`。
- 登录页白色品牌区固定在机构条下方，高度为 `112px`。
- 登录页表单卡片从品牌区下方开始显示，顶部留白为 `24px + 112px + 16px`。
- 登录页底部需要保留浏览器地址栏和系统安全区空间，底部留白为 `112px + env(safe-area-inset-bottom)`。

移动端底部 Tab：

- 固定在屏幕底部。
- 4 个入口：地图、导览、任务、我的。
- 当前 Tab 用顶部绿色线或深色文字强调。
- 移动端主界面顶部品牌区高度为 `112px`。
- 底部 Tab 高度为 `66px`。
- 可滚动页面高度应扣除顶部品牌区，底部内容 padding 需要避开固定 Tab。

移动端地图：

- 地图铺满主体区域。
- 搜索框浮在上方。
- 树木详情使用可拖动 bottom sheet。
- 工单导航也使用地图浮层，不跳到无导航能力的页面。
- 地图页高度应扣除顶部品牌区和底部 Tab，避免滚动页面里嵌套地图。
- 搜索面板固定在地图上方，宽度跟随手机屏幕，左右留 `12px`。

移动端 bottom sheet：

- 默认显示核心信息。
- 支持上滑展开、下滑收起。
- 内容过多时内部滚动。
- 主操作按钮固定在 sheet 底部。
- 拖拽区域应有小横条，不要让用户不知道可以拖。
- 当前树木详情 bottom sheet 保留三档：`compact`、`mid`、`expanded`。
- 点击树木后默认进入 `mid`，保留图片、编号、树种、健康状态、位置、胸径、保护说明和角色操作。
- `expanded` 状态可以显示更多树木详情；`compact` 状态只保留核心识别信息，减少遮挡地图。

导览页：

- 导览位置应是地图上的一个位置坐标，不是“选中某一棵树”。
- 附近树木按导览位置计算距离。
- 附近树木列表应可折叠。
- 打卡按钮必须绿色底白字。
- 导览位置通过地图点选获得，展示为“地图选点 + 坐标”。
- 附近树木默认展开，按距离展示前 8 棵。
- 照片墙默认收起。
- 树木图鉴默认展开。
- 打卡排行默认收起。

任务页：

- 不使用表格。
- 按角色展示不同说明。
- 游客解释“线索是什么”。
- 巡检强调“线索确认、现场复核”。
- 养护强调“现场处置、上传照片、提交复核”。
- 任务以折叠卡片组展示。
- 游客线索组默认收起，包括游客自己的“我的游客线索”和巡检端的“游客线索”。
- 非游客线索的第一个任务组默认展开。
- 工单卡片里的“去现场处置 / 去现场复核”是小型暗红按钮，不占满整行。

我的页：

- 游客不显示工单指标。
- 游客显示打卡、线索、图鉴。
- 巡检/养护可以显示待处理工单类指标。

## 8. 网页端规范

网页端继续保留当前 NYC Tree Map 式布局：

- 顶部黑色城市/机构条。
- 白色品牌区。
- 横向导航。
- 地图和信息面板并列。
- 首页/统计页使用白底、灰边框、绿色强调。

不要把移动端样式反向污染网页端。移动端样式应尽量限制在 `.mobile-*` 命名空间内。

## 9. 交互规则

树木选择：

- 地图点击树木后展示树木详情 bottom sheet。
- 搜索树木后应定位到树木并展示同一张详情卡。
- 详情卡可收起，避免遮挡地图。

导览位置：

- 用户通过地图点选一个位置。
- 也可以通过树木列表快速把位置落在某棵树附近。
- 导览页展示位置名称或坐标，不显示为“选择了某棵树”。

工单：

- 任务页点待处置/待复核工单后，进入地图导航状态。
- 到达后再打开处置/复核表单。
- 工单流程保持：待处置 -> 待复核 -> 已归档；复核不通过退回待处置。

## 10. 后续改动检查清单

每次新增页面或修改 UI 前，检查：

- 是否仍然是白底、黑字、灰边、绿色强调？
- 是否避免了过度圆角、渐变、装饰性背景？
- 主按钮是否为绿色底白字？
- 移动端卡片是否可折叠或可展开，避免占屏过大？
- 地图页是否把地图作为第一视觉？
- 是否出现了“移动端”“demo”“测试”等开发视角文案？
- 游客、巡检、养护看到的文案是否符合自己的角色？
- 是否把样式限制在正确命名空间，避免影响无关页面？
